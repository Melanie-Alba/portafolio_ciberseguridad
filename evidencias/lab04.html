ACTIVIDAD ACADÉMICA

File Path Traversal — Traversal Sequences Stripped With Superfluous URL-Decode

Explotación controlada de una vulnerabilidad File Path Traversal mediante doble codificación URL para evadir un mecanismo de filtrado aplicado antes de una etapa adicional de decodificación.

FECHA 26 / 09 / 2026
TIPO Laboratorio
TECNOLOGÍAS Burp Suite · PortSwigger Web Security Academy · HTTP
02

Objetivo

Identificar y explotar de manera controlada una vulnerabilidad de File Path Traversal presente en la carga de imágenes de una aplicación web. Mediante Burp Suite, se analizó y modificó una petición HTTP para manipular el parámetro filename.

Debido a que la aplicación bloquea las secuencias convencionales de recorrido de directorios, se utilizó doble codificación URL para evadir la validación inicial y acceder al archivo /etc/passwd después de una etapa adicional de decodificación.

03

Desarrollo

El laboratorio se realizó en PortSwigger Web Security Academy utilizando Burp Suite Community Edition. Desde el navegador integrado de Burp Suite se accedió a la instancia del laboratorio y se analizaron las peticiones HTTP generadas por la aplicación.

En Proxy > HTTP history se identificó que las imágenes de los productos eran solicitadas mediante peticiones GET al endpoint /image, utilizando el parámetro filename para especificar el archivo que debía recuperar el servidor. A partir de este comportamiento se seleccionó una de las peticiones para analizar y modificar su contenido.

Análisis de la petición con Repeater

La petición seleccionada se envió al módulo Repeater, permitiendo modificar manualmente sus parámetros y reenviarla al servidor para analizar los cambios producidos en la respuesta.

En este laboratorio, la aplicación implementaba un mecanismo de protección que impedía utilizar directamente las secuencias convencionales de recorrido de directorios ../. Sin embargo, la entrada era sometida posteriormente a una operación adicional de URL decoding.

Para aprovechar este comportamiento, se sustituyó el nombre original de la imagen por el siguiente payload:

..%252f..%252f..%252fetc/passwd

Bypass mediante doble codificación URL

El bypass se realizó mediante doble codificación URL. Normalmente, el carácter / puede representarse mediante URL encoding como %2f. Al codificar nuevamente el carácter % como %25, la representación resultante se convierte en %252f.

De esta manera, cada fragmento ..%252f representa una versión doblemente codificada de la secuencia ../. La entrada puede superar la validación inicial debido a que el separador no se encuentra todavía representado en su forma convencional.

Durante el procesamiento posterior de la solicitud, las operaciones de decodificación transforman las representaciones codificadas hasta reconstruir las secuencias de recorrido. Al repetir esta construcción varias veces fue posible obtener una ruta equivalente a ../../../etc/passwd y alcanzar el archivo solicitado.

Después de enviar la petición modificada, el servidor respondió con HTTP/2 200 OK y devolvió en el cuerpo de la respuesta información correspondiente al archivo /etc/passwd.

La recuperación del archivo confirmó que la doble codificación permitió evadir el mecanismo de validación implementado por la aplicación. La operación adicional de URL decoding reconstruyó las secuencias de traversal y permitió acceder a un recurso situado fuera del directorio autorizado.

Confirmación del laboratorio

Finalmente, PortSwigger Web Security Academy reconoció la recuperación correcta del archivo solicitado y marcó el laboratorio como Solved, confirmando que el objetivo de la práctica había sido completado satisfactoriamente.

04

Resultados

Se explotó exitosamente una vulnerabilidad de File Path Traversal presente en el mecanismo de carga de imágenes de la aplicación.

Mediante la modificación del parámetro filename con el payload ..%252f..%252f..%252fetc/passwd, se comprobó que la validación inicial podía ser evadida utilizando doble codificación URL.

El servidor respondió con HTTP/2 200 OK y mostró el contenido del archivo /etc/passwd, demostrando que una etapa adicional de URL decoding permitía reconstruir las secuencias de recorrido de directorios. Finalmente, PortSwigger Web Security Academy validó la explotación y marcó el laboratorio como Solved.

05

Conclusión

El laboratorio permitió comprender que bloquear únicamente las representaciones convencionales de secuencias como ../ no garantiza la prevención de una vulnerabilidad de File Path Traversal cuando existen diferentes etapas de codificación y decodificación de la entrada.

Mediante Burp Suite fue posible identificar el parámetro filename, modificar su valor y utilizar una representación doblemente codificada como ..%252f para comprobar el comportamiento de la validación implementada por la aplicación.

La recuperación de /etc/passwd demostró la importancia de normalizar y decodificar correctamente los datos antes de realizar las comprobaciones de seguridad. Además, la ruta final debe validarse para asegurar que permanezca dentro de los directorios autorizados.

La actividad también permitió reforzar el uso de HTTP History y Repeater para analizar, modificar y comprobar el comportamiento de peticiones HTTP durante pruebas controladas de seguridad web.
