Laboratorio 03

ACTIVIDAD ACADÉMICA

File Path Traversal — Traversal Sequences Stripped Non-Recursively

Explotación controlada de una vulnerabilidad File Path Traversal mediante secuencias de recorrido anidadas para evadir un mecanismo de filtrado no recursivo.

FECHA 24 / 09 / 2026
TIPO Laboratorio
TECNOLOGÍAS Burp Suite · PortSwigger Web Security Academy · HTTP
02

Objetivo

Identificar y explotar de manera controlada una vulnerabilidad de File Path Traversal presente en la carga de imágenes de una aplicación web. Mediante Burp Suite, se analizó y modificó una petición HTTP para manipular el parámetro filename.

Debido a que la aplicación elimina las secuencias convencionales de recorrido ../ de forma no recursiva, se utilizaron secuencias de traversal anidadas para evadir el filtro y acceder al archivo /etc/passwd.

03

Desarrollo

El laboratorio se realizó en PortSwigger Web Security Academy utilizando Burp Suite Community Edition. Desde el navegador integrado de Burp Suite se accedió a la instancia del laboratorio y se analizaron las peticiones HTTP generadas por la aplicación.

En Proxy > HTTP history se identificó que las imágenes de los productos eran solicitadas mediante peticiones GET al endpoint /image, utilizando el parámetro filename para especificar el archivo que debía recuperar el servidor. A partir de este comportamiento se seleccionó una de las peticiones para analizar y modificar su contenido.

Análisis de la petición con Repeater

La petición seleccionada se envió al módulo Repeater, permitiendo modificar manualmente sus parámetros y reenviarla al servidor para analizar los cambios producidos en la respuesta.

En este laboratorio, la aplicación implementaba un mecanismo de protección que eliminaba las secuencias convencionales de recorrido de directorios ../. Sin embargo, este procesamiento se realizaba de forma no recursiva, por lo que el resultado obtenido después de eliminar la secuencia no era analizado nuevamente.

Para aprovechar esta condición, se sustituyó el nombre original de la imagen por el siguiente payload:

....//....//....//etc/passwd

Bypass mediante secuencias anidadas

El bypass se realizó utilizando la secuencia anidada ....//. Esta construcción permite aprovechar que la aplicación elimina las apariciones de ../ solamente una vez.

Cuando el filtro elimina la secuencia detectada dentro de ....//, los caracteres restantes vuelven a formar una secuencia válida ../. Debido a que el mecanismo no procesa nuevamente el resultado, esta nueva secuencia continúa siendo interpretada durante la resolución de la ruta.

Al repetir esta construcción varias veces fue posible ascender por la estructura de directorios hasta alcanzar el archivo /etc/passwd.

Después de enviar la petición modificada, el servidor respondió con HTTP/2 200 OK y devolvió en el cuerpo de la respuesta información correspondiente al archivo /etc/passwd.

La recuperación del archivo confirmó que las secuencias anidadas consiguieron evadir el mecanismo de filtrado implementado por la aplicación, permitiendo acceder a un recurso situado fuera del directorio autorizado.

Confirmación del laboratorio

Finalmente, PortSwigger Web Security Academy reconoció la recuperación correcta del archivo solicitado y marcó el laboratorio como Solved, confirmando que el objetivo de la práctica había sido completado satisfactoriamente.

04

Resultados

Se explotó exitosamente una vulnerabilidad de File Path Traversal presente en el mecanismo de carga de imágenes de la aplicación.

Mediante la modificación del parámetro filename con el payload ....//....//....//etc/passwd, se comprobó que la eliminación no recursiva de las secuencias ../ podía ser evadida utilizando secuencias de traversal anidadas.

El servidor respondió con HTTP/2 200 OK y mostró el contenido del archivo /etc/passwd, demostrando que el mecanismo de sanitización implementado era insuficiente. Finalmente, PortSwigger Web Security Academy validó la explotación y marcó el laboratorio como Solved.

05

Conclusión

El laboratorio permitió comprender que eliminar únicamente secuencias conocidas como ../ no garantiza la prevención de una vulnerabilidad de File Path Traversal cuando el proceso de filtrado se realiza de forma no recursiva.

Mediante Burp Suite fue posible identificar el parámetro filename, modificar su valor y utilizar secuencias anidadas como ....// para evadir el mecanismo de sanitización implementado por la aplicación.

La recuperación de /etc/passwd demostró que una validación basada únicamente en eliminar patrones específicos puede resultar insuficiente. Es necesario validar la ruta final que será procesada por el servidor y asegurar que permanezca dentro de los directorios autorizados.

La actividad también permitió reforzar el uso de HTTP History y Repeater para analizar, modificar y comprobar el comportamiento de peticiones HTTP durante pruebas controladas de seguridad web.
